# PRD: `berth mcp`, an MCP server for agents (#61)

Status: **done** (stdio; the HTTP transport goes with #62) · Issue: [#61](https://github.com/ar4mirez/berth/issues/61) · Restarts orgs: no

## Problem

An agent on the operator's machine manages orgs by running `berth` and reading its text. The structured operations
layer (#54) exists so that it doesn't have to: the same operations, as typed tools with typed results and errors.

## Decisions (2026-10-07)

- **Tools: the issue's list, plus lifecycle** (`org_up`, `org_restart`, `org_down`), so `--allow-restarts` has
  something to allow.
- **Transport: stdio now.** Streamable HTTP needs the API's authentication (#62) and goes there: an unauthenticated
  server that can manage orgs isn't something to ship.
- **Protocol: the official MCP Go SDK** (`github.com/modelcontextprotocol/go-sdk` v1.8.0). Its client is also what
  the conformance test uses.

## Design

- **A tool is a catalog operation.** `internal/mcpsrv` registers each tool against an entry of `ops.Catalog`, and
  panics for one that has none. What the catalog says decides everything: `Read` always runs; `Write` needs
  `--allow-writes`; a restart (`Restart != Never`) needs `--allow-restarts` and `confirm` equal to the org's name.
  The tool's annotations (read-only, destructive) and the flag named in its description come from the same entry.
- **Reads return the `--output json` documents**, straight from `internal/ops`. Two reads have no command of their
  own: `org_logs` (the log's tail, where `logs` follows) and `backups_list`.
- **Writes run the command's own code** (`app.Fw`, `Repo`, `Backup`, `Up`, …) with its output captured into the
  result. Each call has its own App printing into buffers: the process's stdout carries only the protocol.
- **No tool takes a secret value**, and none returns one. `backup_create` refuses when a backup would ask for a
  passphrase, since there is no terminal.
- **Arguments can't become options.** A value that starts with `-` is refused where it would reach a command line,
  and the SDK validates every call against the tool's schema first.
- **Audit:** every write asked for is appended to `<state>/audit.log` (0600): time, tool, arguments, and `ok`,
  `failed` or `refused`.
- **Resources:** `berth://orgs`, `berth://orgs/{org}`, and the docs and `PARITY.md` (embedded in the binary) as
  `berth://docs/{page}`.
- **`berth --read-only mcp`** stays read-only whatever the flags say: with a flag that allows writes, it doesn't
  start.

## Acceptance criteria

| Criterion (from the issue) | How it is checked |
|---|---|
| A conformance test with an MCP client covers every tool's schema and behaviour | `TestBerthMCPConformance`: every listed tool against the catalog (description, object schemas, annotations, the flag it names), every reading tool called, errors, schema validation, resources. `TestBerthMCPSafety` calls every writing and restarting tool, and fails for a new tool it doesn't call |
| Tests show that writes and restarts are refused without the flags | `TestBerthMCPSafety`: read-only refuses all eight and runs nothing; `--allow-writes` still refuses restarts; `--allow-restarts` refuses a restart without the org's name as `confirm` |
| The docs cover setting it up in Claude Code and Claude Desktop | `docs/guides/mcp.md` |
| Secret values are never returned | `TestBerthMCPConformance` checks every read's result for the fixtures' token |
| Every write through MCP is logged | `TestBerthMCPSafety` reads `audit.log` after each session |

## Not done

- **Streamable HTTP**, by decision: with #62.
- **Progress notifications** for the long tools (`org_up`, `backup_create`): the events exist (#54) and aren't
  forwarded yet. The tool returns when the operation ends, with everything it printed.
- **`repo_remove --delete`**: the tool only quarantines.
