# PRD: `berth serve`, the API (#62)

Status: **done** (`berthd` as a remote host's `Host` implementation stays for later, as the issue says) · Issue: [#62](https://github.com/ar4mirez/berth/issues/62) · Restarts orgs: no

## Problem

Other tools (dashboards, automation, MCP over HTTP) need an API, not a command line to run and parse.

## Decisions (2026-10-07, the maintainer's)

- **`berth serve`**, a command of the one binary, not a separate `berthd`.
- **TCP authenticates with tokens over TLS**: bearer tokens berth issues and stores hashed, each with a scope.
- **This round delivers everything but `berthd` as the `Host` implementation on remote hosts**, as a series:
  the socket API; TCP with tokens; `--via-daemon` for the CLI; MCP over HTTP.

## Design

- **The endpoints are the MCP server's tools.** `internal/mcpsrv` already has each operation as a typed tool with
  the gate, the audit entry and the errors. Each tool now has an `Invoke(ctx, Caller, json)`, and the gate takes
  the **caller** (who asks, and whether they may write or restart) instead of how the server was started. The API
  is an HTTP binding of that: no operation is implemented twice.
- **One route table** (`internal/api.Routes`: method, path, tool, which arguments come from the query). The server's
  handlers, the OpenAPI document (`docs/api/openapi.json`) and the Go client (`internal/apiclient`) are all made
  from it, and tests keep the two generated files current.
- **Arguments** come from the path, the query (for `GET`) and a JSON body, gathered into the tool's input. One that
  the tool doesn't have, or that is given twice, is refused.
- **The socket**: `$XDG_RUNTIME_DIR/berth.sock`, or `~/.config/berth/berth.sock`; mode 0600 from creation (the
  umask is set around `listen`). Its caller may write and restart: it is the user. `--read-only` removes both.
- **Restarts** need `confirm` equal to the org's name, as through MCP.
- **Errors** are `berth.error/v1` documents, with an HTTP status per kind.
- **Streaming**: with `Accept: text/event-stream`, a writing endpoint sends `berth.event/v1` events as the operation
  runs, then a `result` event. `GET /v1/orgs/{org}/logs/follow` streams the log. This is also what the MCP tools and
  the dashboard lacked: the tools can now report progress to a caller that asks.
- **Audit**: the same log as MCP, with `"via":"api"`.

## Tasks

- [x] T1. The socket API: `internal/api`, `berth serve`, the caller-based gate, events.
- [x] T2. The OpenAPI document and the Go client, generated, with tests that keep them current.
- [x] T3. Tests against the real binary over its socket: every endpoint, errors, confirmation, read-only, the
      socket's permissions, a stream.
- [x] T4. Docs: `docs/api.md`, `PARITY.md`, the reference.
- [x] T5. TCP: `--listen`, TLS 1.3 only (a given certificate, or berth's own self-signed one, its fingerprint
      printed for pinning), tokens with scopes (`berth serve token add|ls|rm`; only hashes are kept; checked at
      each request, so a removed token is refused at once).
- [x] T6. `--via-daemon`: the CLI through a running server. The client sends the operation it resolved (ccenv's
      flat form, as `internal/ops` names operations) to `POST /v1/cli`; the server runs that command in-process on
      its own state and streams back what it prints and its exit code, so the text is exactly the command's. Only
      operations the API has endpoints for go; the caller's scope applies; writes are audited.
- [x] T7. MCP over HTTP at `/mcp` (the SDK's streamable handler, stateless), behind the same access: what the
      tools may do is the caller's (a token's scope, per request), which answers #61's open question.

## Acceptance criteria

| Criterion (from the issue) | How it is checked |
|---|---|
| The API test suite runs against the socket | `TestBerthAPI`: every route in the table, through the generated client, against `berth serve`; a route the test doesn't call fails it |
| The OpenAPI spec and handlers stay in sync (CI check) | both are made from `api.Routes`; `TestOpenAPIIsCurrent` and `TestClientIsCurrent` fail on a stale file; the server serves the same bytes |
| Socket permissions are enforced | `TestBerthAPI`: the socket is 0600; a second server and a non-socket file are refused |
| Restart endpoints refuse without confirmation | `TestBerthAPISafety`: up, restart and down with four wrong confirmations each, and with no body: 403, no compose call |
| An unauthenticated TCP request is refused | `TestBerthAPIOverTCP`: no token, a wrong one, and three malformed headers get 401, for a read and for a restart; plain HTTP isn't served; each scope does what it may and no more; a wrong certificate pin is refused by the client |
| The CLI can use a running server | `TestBerthViaDaemon`: eleven commands print exactly what they print directly, with the same exit code, and run nothing on the client; a write changes the server's state and is audited; seven commands that can't go are refused, on the client and at the endpoint |
| MCP over HTTP (from #61) | `TestBerthMCPOverHTTP`: no token, no session; a read token lists the tools and reads, and its write is refused; a write token writes and can't restart; the socket needs no token, and a restart there still needs `confirm` |
| `--read-only`, secrets never returned, an audit log for writes | `TestBerthAPISafety` (read-only), `TestBerthAPI` (no secret in any result; the audit entries, `via` api) |

## Not done, by decision

- `berthd` as the `Host` implementation on a remote host: later, as the issue says.
- A public Go client package: the documents' Go types are internal. The OpenAPI document is the public contract.
